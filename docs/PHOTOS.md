# Optional entry photos

Implemented 5 November 2026. Up to three patient-provided photos per entry, including general-feeling entries. Take a photo opens a live camera view with a framing guide, camera switching, capture preview and retake. Camera access is requested only after that action; tracks stop on close, capture, switching or backgrounding. A file picker remains available when camera access is unavailable or declined. Camera support is device-dependent. There is no backend upload, analytics or image interpretation. The manifest declares the optional camera purpose per FreeAppStore permission guidance: https://docs.freeappstore.online/permissions/ .

JPEG/PNG/WebP inputs and browser-decodable HEIC/HEIF are redrawn locally to JPEG. Unsupported files produce actionable errors. Source limit 20 MB, decoded pixel check 50 MP, longest saved edge at most 1280px, saved payload at most 200,000 characters per image (roughly 150 KB JPEG). Quality starts at 0.9 and is reduced to 0.7 before reducing dimensions. Canvas export strips original metadata, filenames and GPS information; original photos are not retained. Images are resized/compressed patient observations, not verified clinical evidence; users are told to keep originals. No capture date or anatomical location is inferred from image metadata.

Optional captions, previews, enlargement, removal, edit preservation and navigation drafts are supported. Photos render in entry details and printable recaps with a patient-provided label. They are included in JSON backups; imports accept at most 10 MB and validate count, IDs, dimensions, captions and bounded JPEG data URLs (JPEG start/end markers), dropping unrelated fields. This validation does not fully parse or clinically validate image contents.

Storage is the existing versioned localStorage diary. This deliberately bounded first version avoids a separate attachment database and keeps backups self-contained. Browser quotas still limit total diary/photos; save failure retains the form and existing stored diary, rather than claiming success. For large photo histories migrate attachments to IndexedDB with an atomic backup/restore design. Private/local data can still be read by someone using the same browser profile. No changes to authentication or encryption claims.

Verification: build/test suite, backup roundtrip and rejected payload checks, plus browser upload/edit/report checks. Actual device camera capture requires a phone check.
